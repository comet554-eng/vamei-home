# HAFILLER 询盘助手（宁波黑客松「AI＋出海」外贸组）

医美器械厂的外贸业务员把买家询盘贴进来，助手按「理解 → 知识库调用 → 生成 → 校验 → 反馈」出一份可以发的回复，并标出合规、平台规则、合同条款三类风险。业务员用中文提修改要求，进入下一轮。

目前完成的是**工作流 A：询盘理解与回复**。工作流 B（经销商资料本地化与合规预审）还没做。

> `kb/` 里的产品资料来自朋友公司的内部画册，未获授权前不要公开展示或上传。`kb/markets.json` 和 `kb/policy.json` 是示例数据，待确认。

## 运行

### 本次交付

- 顶栏 `EN / 中文` 切换工作台语言；选择保存在当前浏览器。
- 左侧「注册清单」包含沙特、巴西、德国、土耳其四国对照、40 项可筛选任务和 9 个官方核查入口。任务编辑保存在浏览器本地，可导出 CSV。清单是工作初稿，申报前须复核现行法规。
- 询盘助手的校验意见、流程说明和示例标签支持中英文；页面中的「产品客服」继续提供规则库及 AI 模式。
- 项目使用 Python 标准库运行；压缩包不包含 `.env`、本地导入数据、依赖目录及运行日志。

如 8766 端口被其他进程占用，PowerShell 中可运行 `$env:PORT=8777; python app/server.py`，再打开 `http://127.0.0.1:8777/`。

只需要 Python 3.10 以上，不用装任何包。在解压后的文件夹里运行（macOS、Linux 用 `python3`）：

```bash
python app/server.py
```

打开下面两个地址之一：

- http://127.0.0.1:8766/ ：队友做的 MedBridge 工作台网站（`web/`）。
  - 左侧导航「询盘助手」是本项目的询盘工作流：选示例询盘，点「理解并生成回复」。
  - 右下角「产品咨询」是队友做的 HAFILLER 网页机器人，有「规则库」和「AI 模式」两种。
  - 顶栏铃铛是队友做的通知中心；「工作台设置」页底部是产品资料导入。
- http://127.0.0.1:8766/lab/ ：原来的三栏询盘工作台，功能和「询盘助手」页一样。

队友习惯用 `python -m http.server 4173` 在 `web/` 里单独起网站，这样也能用：「询盘助手」页会自动连 `http://127.0.0.1:8766` 的后端，前提是 `app/server.py` 也在运行。网页机器人的 AI 模式和产品资料导入只认同源接口，所以要用 8766 打开。

测试：

```bash
python -m unittest discover -s tests
```

## 网页机器人

来自队友的 MedBridge 源码（Next.js 项目）。`web/widget/` 里是它编译好的挂件，原样复制，没有改。挂件用 Shadow DOM 隔离样式，不影响工作台页面。

- **规则库模式**：完全在浏览器里运行，回答五款填充剂参数，以及报价、认证、物流的待核实边界。不调用后端。
- **AI 模式**：调用 `/api/hafiller-chat`，由 `app/bot.py` 实现，接口格式和队友的 Next.js 版一样。系统提示词在 `kb/bot_prompt.md`，前半段是队友的原文，后半段是本项目补充的规则。

机器人直接回答客户，中间没有业务员把关，所以 AI 模式的每条回复发出前都要过 `app/rules.py`：

1. 有红灯，就让模型按校验意见改一次。
2. 还是红灯，换成保守回复：「需要销售按正式文件核实」。

为了让机器人的中文对话也能被校验，`kb/rules.json` 补了中文词表，比如隆胸、隆臀、「已在哥伦比亚注册」、全球第一、零风险。

## 产品资料导入

入口在「工作台设置 → 产品资料导入」，页面是队友写的 `web/product-import.js`。支持 UTF-8 CSV（列：name、content、source）和 JSON。先预览，确认后保存；同名产品会被更新。`samples/产品资料导入示例.json` 是队友整理的 Derm、Fine Lines 两条，可以直接导入试用。

队友的版本存在 Cloudflare D1 数据库里。这里改成 `app/knowledge.py` 存一个 JSON 文件 `data/product_knowledge.json`。这个文件已经加进 `.gitignore`，因为可能含有内部资料。校验规则和队友一样：
- 每次 1–200 条。
- 名称不超过 120 字，资料不超过 8000 字，来源不超过 300 字。
- 不收膝关节和眼科产品。
- 名称不分大小写，总数最多 200 款，文件最大 1 MB。

导入接口只接受本机工作台页面的提交：Host 必须是 localhost 或 127.0.0.1，Origin 必须和 Host 同源，所以别的网站、本机别的端口都提交不了。

导入的资料只给网页机器人用，「询盘助手」页仍然只读 `kb/products.json`：
- **规则库模式**：问到已导入的型号时，直接显示导入的原文。这段在浏览器里运行，不经过规则校验，所以只能导入核实过的内容。
- **AI 模式**：取最近 3 条消息里提到名字的导入资料，最多 8 条，作为事实数据发给模型。回复照常过规则校验。

想恢复成没导入过的状态，删掉 `data/` 目录即可。

## 接入大模型

复制 `.env.example` 为 `.env`，填 `HA_LLM_PROVIDER`、`HA_LLM_API_KEY`、`HA_LLM_MODEL`。支持 Anthropic 和任何 OpenAI 兼容接口。不填就是离线模板模式：理解用关键词规则，生成用模板，修改指令不生效，页面右上角会显示「离线模板」。

用当前模型把 `samples/` 里的示例全部跑一遍（每条跑初稿和一轮修改，各示例并行），结果存到 `runs/`：

```bash
python scripts/run_samples.py
```

2026-10-31 用 claude-opus-5.5 实测：理解一步约 8 秒，生成一步 10 到 20 秒；三条示例并行共 44 秒，串行要 114 秒。

**第一轮理解和生成同时跑**（`app/pipeline.py` 的 `_first_round_parallel`）：模型理解放到后台线程；同时用关键词规则的预判直接起草。理解结果回来后，如果国家、买家类型、回复语言、型号四项和预判一样，预判稿就是正式稿；不一样就按模型理解重写，这时和原来串行一样慢，多花一次生成的 token。校验永远按模型理解跑。第二轮起沿用上一轮理解，只有生成一步，不受影响。

2026-11-01 实测（同一模型，三条示例预判全部命中）：第一轮用时哥伦比亚 28.3→15.7 秒、美国 24.0→16.8 秒、英国 20.0→10.8 秒；三条示例并行共 33.7 秒。

## 数据流

```
买家询盘（任何语言）
  │
  ├─1 理解：模型抽取语言、国家、买家类型、意图、型号、问到的用途；关键词规则补漏
  │
  ├─2 知识库调用：按型号取 kb/products.json 的字段（带来源页和矛盾标记），
  │              按国家取 kb/markets.json 的准入状态，取 kb/policy.json 的商务政策
  │
  ├─3 生成：模型按渠道（阿里国际站 / 邮件）写回复和中文对照；只能用第 2 步的事实
  │
  ├─4 校验：app/rules.py 跑 11 条规则，不调用模型，同样的输入结果一样
  │
  └─5 反馈：页面上原文标红黄、列出问题和修改建议、显示每一步用时和模式
        │
        └─ 业务员写中文修改要求，或点「按校验意见修改」，或手改后「重新校验」→ 回到第 2 步
```

每一轮的 `trace` 都会显示在页面右下角：每一步用的是模型、规则、模板还是手改，用了多少毫秒，出了什么错。`wall_ms` 是整轮实际用时；第一轮因为理解和生成并行，各步相加会比它长。

## 校验规则

| 编号 | 类别 | 规则 | 等级 |
|---|---|---|---|
| C1 | 目标国合规 | 推荐隆胸、隆臀等身体部位用途（否定句除外） | 红 |
| C2 | 目标国合规 | 未注册或状态未知的国家，回复却声称已注册或可清关 | 红 |
| C2 | 目标国合规 | 国家注册状态未知或未识别国家 | 黄 |
| C3 | 目标国合规 | 买家是个人或要自行注射，回复没有婉拒 | 红 |
| C4 | 目标国合规 | 美国买家：提到 FDA 但没否认，或没说明未获 FDA 批准 | 红 |
| C5 | 目标国合规 | 「无副作用」「永久」「无需皮试」等绝对化说法 | 黄 |
| C6 | 目标国合规 | 临床百分比或病例数没有出处 | 黄 |
| P1 | 平台规则 | best、No.1、top 10 等最高级用语（落款 Best regards 除外） | 黄 |
| P2 | 平台规则 | 点名竞品，如 Restylane、Juvederm | 黄 |
| K1 | 合同条款 | 问了价格但缺贸易术语、币种、MOQ、有效期、付款方式；有占位符要手填 | 黄 |
| K2 | 合同条款 | 独家代理、价格保护、保证注册等超出权限的承诺 | 红 |
| K3 | 合同条款 | 型号规格不在产品库里，或只出现在部分资料里 | 黄 |

**等级**：红 = 不能发，必须改；黄 = 可以发，但要人工确认；绿 = 通过。

**反馈方式**：
- 原文标红黄，并附规则编号。
- 列出问题清单，附原因和修改建议。
- 显示和上一轮的差异对比。

词表在 `kb/rules.json`，改词表不用改代码。

## 异常处理

| 情况 | 处理 |
|---|---|
| 没配置模型 | 理解用关键词规则，生成用离线模板，页面提示 |
| 模型返回 429、5xx 或连接失败 | 等 1.5 秒、3 秒各重试一次 |
| 重试后仍失败，或其他 HTTP 错误 | 这一步退回规则或模板，trace 里显示错误原因 |
| 模型输出不是合法 JSON | 重试一次，仍失败按上一条处理 |
| 模型返回的字段不合法 | 枚举值不对就用规则结果；意图、型号取两者并集 |
| 知识库字段有矛盾或可疑 | 发给模型时带上状态，要求不得当作事实；页面上标红 |
| 国家不在知识库 | 校验出黄灯，提示补 `kb/markets.json` |
| 请求为空或过大 | 返回 400，页面弹出提示 |

## 目录

```

app/rules.py       校验规则引擎

app/llm.py         大模型调用（Anthropic / OpenAI 兼容）

app/knowledge.py   产品资料导入的存储（data/product_knowledge.json）
app/static/        原来的三栏询盘工作台（/lab/）
web/               队友的 MedBridge 网站；inquiry.js、inquiry.css 是本项目加的「询盘助手」页，其余是队友的原文件

```

## 平台配置

本项目没有用低代码平台，配置都在仓库里：模型配置在 `.env`，提示词在 `app/pipeline.py` 的 `UNDERSTAND_SYS` 和 `GENERATE_SYS`，规则词表在 `kb/rules.json`，知识库在 `kb/`。

## 第三方组件声明

- 后端只用 Python 标准库，没有第三方包。
- 大模型 API：运行时调用 `.env` 里配置的服务商，属于外部服务。
- `web/`：队友的 MedBridge 工作台页面。页面从 unpkg 加载 Lucide 图标库（ISC 许可），断网时图标不显示，功能照常。
- `web/widget/hafiller-widget.js`：队友用 Vite 编译的网页机器人，内含 React 和 React DOM（MIT 许可）。源码在队友的 MedBridge 源码包里。
- 产品资料：Zhejiang Jingjia Medical 的画册和参数表，使用前需取得授权。

## 已知限制

- 校验词表只覆盖英语和西语，回复语言因此只开放这两种。
- 否定句判断靠词语前后 60 个字符内有没有否定词，复杂句子可能误判。
- 离线模板不理解修改指令。
- 只用三条自编示例测过真实模型，还没用真实询盘测试过。
